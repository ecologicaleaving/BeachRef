### Current Problematic Interfaces
**Source: [types/match.ts]**
Current `BeachMatch` interface uses all string types, causing:
- Type conversion errors in production
- Inconsistency with VIS API numeric responses  
- Field naming misalignment with VIS schema

**Fragmented Interface Problem:**
**Source: [docs/architecture/vis-api-data-structure-improvement-plan.md#data-model-fragmentation]**
Currently 4 different match interfaces exist:
- `BeachMatch` (types/match.ts) - All string types  
- `BeachLiveMatch` (types/beach-live.ts) - Live match data
- `BeachMatchCore` (types/match-v2.ts) - Domain model v2
- API types (types/api-v2.ts) - API response types

This fragmentation causes type confusion and conversion overhead.
