# Story 7.4: Cleanup & Optimization

**Status**: Draft
**Epic**: EPIC-007 Data Architecture Restructuration
**Phase**: 4 - Cleanup & Optimization
**Priority**: High
**Estimated Effort**: 3-5 days

## Story Statement

As a **BeachRef development team**, I want to **remove legacy code components and optimize bundle size** so that **the application achieves 30% bundle size reduction, 40% memory usage improvement, and maintains production stability with the new data architecture**.

## Acceptance Criteria

### AC1: Legacy Code Removal
**Given** the new repository and transformation layers are fully functional
**When** I remove legacy Tournament interface and old VisApiService
**Then** all components use TournamentCore and new repository patterns
**And** no legacy type imports remain in the codebase
**And** all tests pass with new interfaces

### AC2: Bundle Size Optimization
**Given** legacy code has been removed
**When** I analyze the production bundle
**Then** bundle size is reduced by at least 30% from baseline
**And** webpack bundle analyzer shows no redundant dependencies
**And** tree-shaking effectively removes unused code

### AC3: Memory Usage Optimization
**Given** the optimized bundle
**When** I profile memory usage in production scenarios
**Then** memory usage is reduced by at least 40% from baseline
**And** no memory leaks are detected during extended usage
**And** garbage collection cycles are optimized

### AC4: Production Deployment Validation
**Given** all optimizations are complete
**When** I deploy to production with monitoring
**Then** all performance KPIs meet or exceed targets
**And** application stability is maintained
**And** user experience metrics show improvement

### Legacy Code Removal Analysis

**Files identified for removal based on Epic 7 requirements:**

**Legacy Tournament Interface (`types/tournament.ts`):**
- 99+ optional fields creating type uncertainty [Source: EPIC-007-data-architecture-restructuration.md#current-architecture-pain-points]
- Should be completely replaced by TournamentCore interface [Source: types/tournament-v2.ts]
- Currently imported by: TournamentDetail.tsx, TournamentSelectionScreen.tsx, TournamentList.tsx, and various services

**Legacy VisApiService (`services/visApi.ts`):**
- Contains complex 2000+ lines of fallback logic [Source: EPIC-007#api-strategy-problems] 
- Should be replaced by unified VisApiClient [Source: services/api/VisApiClient.ts]
- Currently used by: CacheService.ts, multiple screen components, and test files

**Additional Legacy Components to Remove:**
- `services/VisApiServiceFactory.ts` - Factory for old VisApiService
- Legacy test files using old interfaces
- Unused transformation utilities that bridge old/new systems

### Bundle Optimization Strategy

**Target: 30% bundle size reduction** [Source: EPIC-007#phase-4-deliverables]

**Optimization Areas:**
1. **Dead Code Elimination**: Remove legacy Tournament interface and associated utilities
2. **Dependency Cleanup**: Remove unused imports from legacy VisApiService patterns
3. **Tree Shaking**: Ensure new modular architecture supports effective tree shaking
4. **Webpack Configuration**: Optimize build configuration for production bundle

### Memory Optimization Strategy

**Target: 40% memory usage reduction** [Source: EPIC-007#success-criteria]

**Optimization Areas:**
1. **Cache Memory Management**: Leverage new SmartCacheManager for optimized memory usage
2. **Component Memory**: Ensure TournamentCore immutable patterns reduce memory overhead
3. **Service Cleanup**: Remove memory-intensive legacy service instantiations
4. **Garbage Collection**: Optimize object lifecycle with new repository patterns
